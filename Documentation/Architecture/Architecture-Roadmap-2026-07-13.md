# Architecture Documentation Roadmap
*Documentation/Architecture | 2026-07-13 | Compiled by Claude (Design Consultant) at v1.3.4.3, feature 001 in flight*

**What this is:** an index of every document in this folder, the project arc they tell — where we've been, where we are, where we're going — and a curated suggestions list for features and optimizations, drawn from the docs, the 2026-07-12 full review, and the corpus history.

**Scope note:** there are TWO Architecture folders. This one (root `Documentation/Architecture`) holds the design-era and living documents. The inner `DSP_Processor/Documentation/Architecture` holds 18 January diagnostic-era analyses (indexed in §3). Merging the trees remains an open hygiene item.

## 1. The Eras — how to read this folder

The documents cluster into five eras, and knowing which era a doc belongs to tells you how to trust it:

- **Era 1 — Pipeline archaeology (Jan 11–16).** Diagnostic deep-dives from when the audio path was being debugged into stability. Mostly in the inner tree. Historically accurate, superseded in detail.
- **Era 2 — The state-machine design sprint (Jan 17).** One extraordinary day (corpus conv 8884) produced the GSM/SSM/Coordinator/Registry/Thread-Safety design set. The architectural DNA of the project.
- **Era 3 — The cognitive layer (Jan 18).** Self-awareness built on the State Registry foundation: cognitive patterns, then the Introspective Engine v2.0 design.
- **Era 4 — Phase 7 SSM expansion (Jan 19).** The four "missing" SSM designs plus roadmap and review. All four are now implemented (Phase 7.2).
- **Era 5 — The SpecKit era (Jul 12–13).** Living documents generated by governed features: tap semantics (003), subscriber audit (002). Plus this roadmap.

## 4. Where We've Been

**January:** Phases 1–6 built the DAW — audio I/O, DSP thread with ring buffers, recording, playback, FFT/meters, gain stages — then the Jan 17 design sprint retrofitted deterministic architecture: GSM + SSMs + Coordinator + State Registry + thread-safety patterns. The cognitive layer followed (v1.x, then Introspective v2.0). Phase 7 designed and (by spring) implemented the four modeful SSMs. The whole era ran on Copilot + Rick, with the AI-memory pain from this exact project seeding ForgeCharter → RDF → MemOS.

**July 12–13 (the SpecKit weekend):** Full-project review (8 verified bugs, perf findings, strategic Int16 diagnosis) → constitution v1.0→v1.1 ratified → **v1.3.2.5** punch list (all 8 bugs + hygiene) → **v1.3.3.1–.3** feature 003: test foundation (55→67 tests), overrun detection, single monitoring API → **v1.3.4.1–.3** feature 002: truthful lossless deferral, delivery outside the lock in commit order, process-lifetime coordinator — with the 003 matrix suite surviving the engine rewrite with an **empty diff**. Along the way: the Stereo Mix incident (diagnosis-before-fix, zero code changed), the corpus synopsis, and the pan-law step-discontinuity discovery.

## 5. Where We Are — v1.3.4.3, feature 001 in flight

**001-float32-pipeline** (branch, v1.3.5.x): the domain migration. Float end-to-end, integer PCM only at boundaries, single canonical conversion, balance-law pan (center unity, favored channel unity, no boost — Architect-ruled), no dither (deferred with 24-bit export), time-semantics buffer sizing. Test contract: matrix + tap suites survive untouched; processor math re-derived in float; new bit-transparency null (full-math ×2→×0.5 variant), headroom, and denormal-timing tests. This discharges the constitution's "Int16 is legacy" clause and unblocks everything in §6.

## 6. Where We're Going

**Committed next: 004 — Scarlett 18i8 + ASIO + loopback.** AudioDeviceSSM finally exercises its ASIO state; multichannel input (18-in changes the stereo assumptions); channel mapping UI; `WasapiLoopbackCapture` as a real input source (the Stereo Mix incident is the justification paragraph — driver virtual devices are update-fragile). The corpus already holds the vision: "Scarlett after the RC-505, as multitrack recorder + digital patchbay."

**The payoff arc (post-001, rough order):**
1. **Processor library** — SVF-based EQ (HPF, shelves — the nested-SVF corpus idea), then the Blumlein chain stages (M/S encode → per-domain multiband → M/S decode). The 9-stage Blumlein ribbon chain is the flagship deliverable the float migration exists for.
2. **High-res stereo sonagram** — FFT waterfall, paint-only control, L/R and **M/S display modes** (uniquely valuable for Blumlein work). First new consumer of the 003 tap API. ~2–3 Recursions.
3. **24-bit export + TPDF dither** — deferred from 001 by design; a flag on the canonical conversion.
4. **StateMachineUI** (design on file) — 002's strictly-ordered event stream is the perfect data source; the State Debugger panel grows into the visualizer.
5. **PipeLineUI full vision** (design on file) — drag-to-route stage graph over AudioRoutingSSM.
6. **State Registry codegen** (Registry-Implementation-Plan's open half) — YAML → generated transition tables; the exhaustive matrix test is the ready-made oracle that makes generation safe.
7. **Reactive streams formalization** (reactiveStream.md) — a typed observable event bus over the 002 delivery spine for meters/UI, replacing residual timer polling.

**Standing debt (tracked, unglamorous):**
- **RecordingEngine.vb:472 `Thread.Abort()`** — throws `PlatformNotSupportedException` on .NET 10 when reached; recording stop path. Fix = cancellation flag + Join (the feeder pattern). *Should ride along with 001's US on the record path or immediately after.*
- **Mojibake sweep** — ~15 files, load-bearing in Cognitive parsers (`" ? "` split in PredictionEngine.vb:153); needs coordinated parser+data migration, accepting both separators.
- **MainForm slimming** (1,849 lines; Phase 7 objective #5) — mechanical now that SSMs exist; slims naturally as features touch handlers.
- **Docs-tree merge** (two Documentation trees) + rename pass in this folder.
- **Thread-Safety-Patterns.md update** — document the 002 single-drainer model and R1-RESIDUAL as a new Part.

**Optimizations (from the 07-12 review, still open, none urgent):**
- **P3** — replace the DSP worker's wall-clock pacing with output-buffer backpressure (simpler, sample-rate-agnostic; `Sleep(1)`'s ~15.6 ms real resolution stops mattering entirely).
- **P5** — meter/FFT paths: reusable scratch buffers, and replace ThreadPool-per-event FFT dispatch with a single consumer (ordering + zero churn). Partially improved by 001's conversion-loop deletions.
- **P4** — MultiReaderRingBuffer single-lock contention: documented honestly per 003; a per-reader SPSC design only if profiling ever demands it.
- **P6** — gate the remaining hot-path diagnostics (peak scans, call counters) behind debug level checks.
- **D2** — playback position from consumed bytes instead of wall clock (enables pause, survives underruns; TransportControl accuracy).
